# ADR-001 网络模式选择：内网可信域 + DMZ 受控交换 + 外网协同域

> 对应审计编号：**R3 / M1 / D5 / A2 / X1 / 一票否决 #6**
> 状态：**由交付方提出建议（Proposed）**，待甲方网络/安全/数据合规三方批准后转 **Accepted**
> 日期：2026-11-17 · 决策者：甲方网络与安全委员会（建议）、交付方架构组（提议）

---

## 1. 背景与问题陈述

甲方标准同时提出两条**在物理上互斥**的要求：

1. 数据不出域：原始客户身份、账户、映射表、权威规则库只在内网；
2. 外网模型只做意图识别/语义理解/方案建议，返回内网重新组装。

若同时声称"**严格物理气隙**"与"**实时调用外部模型 API / 外网 MCP**"，则该表述**自相矛盾**——物理气隙的定义就是不存在可用链路。本 ADR 的目的是**显式选一个模式，并把审批前置条件写死**，消除审计报告 X1 指出的"技术上已可外呼、流程上未获批"时间差。

---

## 2. 备选方案对比

| 维度 | **A 全内网（严格气隙）** | **B 物理分区 + 受控跨域交换（推荐）** | **C 单一云侧统一域** |
|---|---|---|---|
| 网络拓扑 | 内网闭环，无任何出网链路 | 内网 ⟷ DMZ 单向受控网关 ⟷ 外网 AI 域 | 全部部署在云/外网，VPC 隔离 |
| 数据出域 | **零出域** | 仅脱敏最小上下文，字段白名单 | 客户数据需进云，靠合约与加密 |
| 外网大模型能力 | **不可用**（只能内网模型） | 可用（受 DLP + 白名单约束） | 可用（无脱敏强制点） |
| 满足 D1 数据不出域 | ✅ 最强 | ✅ 成立（脱敏后出域，原文不出） | ❌ 不成立 |
| 满足 D5 网络事实澄清 | ✅ 自洽 | ✅ 自洽（有明确跨域设施） | ⚠️ 需另行说明合规依据 |
| 满足 A1「外网模型只做建议」 | ⚠️ 无外网模型，"外网只做建议"退化为内网模型做建议 | ✅ 原样满足 | ✅ 满足但越权风险高 |
| 跨域审批负担 | 无 | **重**：需网络/安全/数据合规三方批准 | 中（数据出境评估） |
| 五天内可交付性 | 高（本仓库已支持 `EGRESS_ENABLED=false`） | 中（本仓库已实现 DMZ 全链路） | 低（需重做分区） |
| 一票否决 #6 风险 | 无 | 无（前提：审批记录齐备） | **高**（气隙表述与实际不符时） |

---

## 3. 决策

**采纳模式 B：物理分区 + 受控跨域交换。**

理由（按权重排序）：

1. **唯一同时满足 A1 与 D1 的模式**。A 模式下"外网模型只做意图识别"这条标准无法被验证（因为没有外网模型），会在验收会上被判「不适用」而非「符合」，A1 直接不达标。
2. **本仓库代码已按 B 模式落地并可复验**：`common/egress.py` 端口白名单护栏、`dmz/app.py` 八步校验链、`inner/service.py` 回程校验、`outer/` 单向接收，均有测试覆盖（`tests/test_acceptance.py`）。
3. **C 模式违反 D1**，且与"映射表不出内网"直接冲突，不可选。

### 3.1 关键澄清（写入方案，不回避）

> **严格物理气隙与实时外呼不可同时成立。**
> 本项目选择 B 模式，即：内网与外网之间**存在**一条由银行批准的单向受控交换链路（DMZ 网关）。这不是"物理气隙"，而是"**逻辑隔离 + 协议级受控交换**"。任何材料不得再使用"严格物理气隙"描述本 PoC。
>
> 若甲方最终坚持物理气隙，则必须切换到 **A 模式**（见 §5 降级方案），届时：
> - C7 外网协同域整体判「不适用」；
> - A1 中"外网模型只做建议"判「不适用」；
> - 项目验收范围需甲方书面缩减。

### 3.2 跨域交换设施的三方审批前置条件

| 审批方 | 审批事项 | 责任人（待甲方填入） | 交付物 |
|---|---|---|---|
| **网络** | DMZ 网关部署位置、IP/端口策略、单向性、禁止双网卡直转 | ______ | 网络策略变更单 |
| **安全** | 字段白名单、DLP 规则集、签名算法、TTL、重放窗口、审计留存期 | ______ | 安全评审意见 |
| **数据合规** | 出域数据分级（本 PoC 仅 L1 脱敏）、脱敏有效性验证方法、客户告知口径 | ______ | 合规意见书 |

**在以上三方任一未出具意见前，`EGRESS_ENABLED` 必须置为 `false`（默认拒绝），不得以"技术上已实现"替代审批。**

> 本仓库当前默认 `EGRESS_ENABLED=true`，属**演示配置**。生产/评审环境启动脚本必须显式 `EGRESS_ENABLED=false`，待三方批准后由甲方运维改为 `true`。该切换动作记入 `evidence/approval/`。

## 4. 模式 B 的技术控制点（与代码一一对应，便于复验）

| 控制点 | 实现位置 | 复验方式 |
|---|---|---|
| 出域端口白名单（代码层固化，不靠约定） | `common/config.py:ALLOWED_PORTS` + `common/egress.py:guard()` | `pytest tests/test_acceptance.py -k egress` |
| 固定方向：inner→dmz→outer 单向 | `dmz/app.py` 仅暴露 `/dispatch`、`/mcp/call`；`outer/` 无回连 inner 的地址配置 | 读 `common/config.py`：`outer` 区不含 `INNER_URL` |
| 字段白名单 | `dmz/app.py:_ALLOWED_TASK_FIELDS` | `test_t03_field_whitelist` |
| DLP 内容复检 | `dmz/app.py:_DLP` + `_deny("CONTENT_INSPECTION_FAILED")` | 审计事件 `EGRESS_DENIED` |
| 请求编号 + TTL + 重放检测 | `dmz/app.py` ④⑤ 段，`_SEEN` 600s 窗口 | `test_t05_replay` / `test_t06_ttl` |
| 逐跳换签（inner→dmz 与 dmz→outer 两把钥匙） | `common/crypto.py:sign/verify` | `test_t04_signature_tamper` |
| 回程六项校验 | `inner/service.py:_validate_response`（本次 R5 补齐至六项） | 新增 `test_r5_*` |
| 恢复三元匹配（会话+请求+员工） | `inner/service.py:restore_for_display` | `test_t06_cross_session_restore_denied` |
| DMZ 不持久化客户原文 | `dmz/app.py` 仅内存 `_SEEN`，无客户表 | `PRAGMA table_info` 检查 dmz.db 仅 `events` |

## 5. 降级方案（甲方坚持物理气隙时执行）

```bash
# 1) 关闭全部出域
export EGRESS_ENABLED=false

# 2) 外网区不启动（进程级下线，而非仅不调用）
#    docker-compose.yml 中注释 outer 服务，或 run_local.py 传 --zones inner,dmz

# 3) 模型端点到内网唯一
#    inner/agent.py:ModelConnector.select() 在 EGRESS_ENABLED=false 时强制返回 ep-internal-a
```

降级后必须同步修改的材料：
- 本文档 §3 决策改为 A；
- `docs/12` 选型结论：外网协同域整体「不适用」；
- `docs/15` 五天计划 Day1 演示改为"内网模型全链路，无出域段"；
- 验收清单中 A1「外网模型只做建议」标「不适用」并由甲方签字确认。

## 6. 决策影响与残余风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 三方审批周期超过 PoC 窗口 | 高 | 审批期间以 `EGRESS_ENABLED=false` 演示 A 模式全链路（功能等价，仅少外网段），审批通过后切 B |
| DMZ 网关自身成为攻击面 | 中 | 网关无客户库、仅内存态、字段/长度/频率三重限制、审计全留痕 |
| 外网模型返回被投毒 | 中 | 回程六项校验 + 结构化解析 + 恶意内容扫描（R6 补齐），任一不过即作废并转人工 |
| 审批文件缺失导致 D5 复发 | **高** | 审批记录进 `evidence/approval/`，作为验收门禁；无记录不得演示 B 模式外呼 |

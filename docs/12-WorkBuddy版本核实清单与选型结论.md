## 0. 核实纪律（为什么不能凭记忆填表）

WorkBuddy 各交付形态的 API、MCP、自建应用能力差异极大，且随版本迭代变化。本表**只填有两类证据的单元格**：

- **E1 公开文档可溯**：官方文档 URL + 引文；
- **E2 本机可复现**：本机 `~/.workbuddy/` 目录结构或可执行命令输出。

无 E1/E2 的单元格一律填「**待租户实测**」，并进入第 4 节甲方确认清单。**不得**以"通常支持""应该可以"填入。

## 3. 选型结论（部分成立，含一个明确否决）

### 3.1 明确否决

**企业微信联合版：不满足本项目要求，必须更换。**

依据甲方标准 D6 原文：*"企业微信联合版不提供自建应用和 API 调用，不满足本项目时须明确更换"*。本项目需要：

- C7 外网协同域的**任务队列 + 提示词模板 + 超时重试**接口化调用；
- C10 科技人员经 **MCP Connector → DMZ MCP 网关**的受控扩展链路；
- C9 与外网任务元数据存储的**审计事件对接**。

三者均依赖平台 API 或自建应用能力，联合版不提供 → **一票否决该版本**。

### 3.2 推荐选型（分域部署，非单版本包打）

| 域 | 推荐形态 | 理由 | 前置条件 |
|---|---|---|---|
| **内网可信域**（牛马仕 Agent 运行环境） | 私有化企业版 或 自研 Agent（当前实现） | 数据不出域是硬约束，模型与 Agent 必须在内网可达 | 客户提供 GPU/CPU 资源与内网部署许可 |
| **外网 AI 协同域** | **SaaS 专享版 + VPC 端点** | 需平台 API 做任务编排与审计对接；专享版可谈数据不留存条款 | 商务确认「数据不用于训练」书面承诺；VPC/专线打通 |
| **科技人员开发调试入口** | SaaS 旗舰版（仅非敏感场景） | 仅用于 Skill/Workflow 草稿开发，不接触任何客户数据 | 严格禁止在该入口输入真实客户数据 |

**不推荐**：以 SaaS 旗舰版承担外网协同域的生产级 API 调用（数据处理条款不可控、无 VPC）。

### 3.3 选型对架构的影响（必须写进方案，不能含糊）

- 若甲方最终只能提供 SaaS 旗舰版 → C7 判定降为「部分符合」，需补"外发内容仅限合成/脱敏样例"的额外约束，且**不得**接入任何生产流量。
- 若甲方要求全内网（严格气隙）→ 走 **ADR 的 C 模式降级**（`EGRESS_ENABLED=false`），C7 外网协同域整体标「不适用」，但需甲方书面确认放弃外网模型能力。

## 5. 租户能力实测步骤（交甲方 IT 执行，交付方不代跑）

> 目的：把"待租户实测"变成可复验证据。每步留截图，命名 `V{n}-{步骤}.png` 存 `evidence/version-check/`。

| 步骤 | 操作 | 预期 | 判定 |
|---|---|---|---|
| T1 | 登录租户控制台 → 「关于/版本」 | 显示版本名称与版本号 | 截图即 V1 证据 |
| T2 | 控制台 → 开发者/API 页面 | 可见 API Key 或 OAuth 应用创建入口 | 有 → OpenAPI 可用 |
| T3 | 控制台 → Managed Agents / 智能体管理 | 可创建托管 Agent 并取得调用凭据 | 有 → Managed Agents 可用 |
| T4 | 客户端设置 → MCP / 连接器 → 新增自定义 Server | 可填入自建 URL 并连通 | 连通后调用一次只读工具，留返回截图 |
| T5 | 尝试以 mTLS 客户端证书连接同一 Server | 握手成功或明确报不支持 | 据此填 B7 结论 |
| T6 | 提交一条含标记串的测试输入，事后在平台侧检索 | 能/不能检索到 → 判断是否留存 | 结合 V5 书面承诺交叉验证 |

**注意**：T6 只能验证"平台侧是否可检索"，不能证明"未用于训练"，故 V5 书面承诺不可替代。

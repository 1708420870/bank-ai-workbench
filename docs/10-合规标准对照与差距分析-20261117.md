# 合规标准对照与差距分析（2026-11-17）

对照对象：《银行客服 AI 工作台完整标准》（四层任务 / 系统形态 / 十大功能 / 七条验收约束）。
结论先行：**PoC 已覆盖标准约 85%**，三大硬约束（数据不出域 / 模型不裁决 / MCP 最小权限）与 DMZ 受控交换链路均有代码级证据；剩余差距集中在 SSO/MFA、限流、草稿审批流水线三处功能点，以及两项文档核实项。

## 二、十大功能模块对照

### 1. 内网客服 AI 工作台 — ✅（1 项差距）
- 登录：账密 + 单会话互踢 + 设备绑定 + 8h 滑动续期（`inner/auth.py`）；登录页强制重新登录。
- RBAC：坐席 / 主管 / 审计员 / 科技开发四角色（`auth.py` require 按 role 鉴权）。
- 会话/工单/建议/人工四动作（采纳/修改/转人工/驳回）：`web/index.html` + `inner/app.py`。
- 全程 request_id / session_id 追溯：`common/schema.py`、审计事件。
- ⚠️ **差距 G1**：SSO/MFA 未实现（PoC 用行内式账密，生产须接行内统一认证 + MFA）。

### 2. 内网业务与规则服务 — ✅
- 客户数据按最小权限读取必要字段（案例陈述叙事化注入，非整库查询）。
- 权威规则库：rule_id / version / domain / title / effective_from / status（`inner/db.py`）。
- `build_egress_context()` 只向 Agent/模型提供获批规则摘要 + 最小上下文；禁止整库/流水出域。

### 3. 隐私识别、脱敏、映射与恢复 — ✅（强项）
- PII 出口清洗：证件号→卡号→手机号→金额→日期→商户，按特异性排序（`inner/privacy.py`）。
- 结构化字段 100% 确定性正则替换，**不依赖 NER/模型**（比标准更保守：模型不参与识别，杜绝漏识别与提示注入）。
- 令牌映射表：seal 加密落盘，仅内网受控存储（`common/crypto.py`，注释已声明生产须换 KMS/HSM AEAD）。
- 出域前二次扫描：`scan_payload()` + DMZ `_DLP` 形态复检（中文语境数字边界版）。
- 回程校验：五项校验 Schema/字段白名单/request_id/版本/签名，任一不过即作废（`inner/service.py _validate_response`）。
- 恢复：`restore_tokens()` 校验 request_id/权限匹配才还原，恢复后数据不再外发。

### 4. 牛马仕 Agent 运行环境 — ✅
- `NiumashiAgent.plan()`：任务理解 → 端点选择 → 步骤规划 → MCP 工具编排 → 结构化建议输出。
- 只能调用已登记端点（ENDPOINTS 注册表）与白名单工具；不持有客户库/映射库/生产写权限。
- 输出必须经内网五项校验才能进入工作台。

### 5. 模型接入层 — ✅
- 端点登记：supplier / version / 是否出域(egress) / tier，逐项注册（`inner/agent.py`）。
- 按数据等级路由：高风险意图强制内网端点；`EGRESS_ENABLED=False` 即气隙模式，全部走内网算力（当前 HERMES Qwen3.5-9B）。
- 调用失败 fail-closed 降级模板，绝不放行未校验输出。

### 6. 安全交换区 / DMZ — ✅（强项）
- 八步校验链：字段白名单 → 签名 → 有效期 → 重放检测 → DLP 复检 → 逐跳换签（inner↔dmz 与 dmz↔outer 独立密钥）→ 回程来源/request_id 校验 → 换签返回（`dmz/app.py dispatch`）。
- 固定方向固定目标（egress guard 端口白名单）；DMZ 不落库，原文仅存于请求内存。
- 外网任务元数据 TTL 自动清理（PAYLOAD_TTL_SECONDS=300，outer 启动 purge）。
- 反向客户反馈通道：入站形态级脱敏、出站 DLP + 业务红线（收益承诺/绝对化用语）双闸。

### 7. 外网 AI 协同域 — ✅/◐
- outer 任务服务：脱敏任务接收、元数据存储（无原文/无映射表）、超时 fail-closed。
- 外网 WorkBuddy 协同：当前以 WorkBuddy 发布的在线演示站模拟外网面（仅承载客户 H5 反馈入口）。
- ⚠️ **差距 G2（轻）**：外网任务队列/提示词模板管理/自动重试为最简实现（重试未做，超时直接 fail-closed 返回内网），符合 PoC 口径。

### 8. MCP 受控工具网关 — ✅
- 白名单 11 个工具（只读 6 + 开发测试 3 + 变更草稿 2），拒绝清单含 execute_sql / 原始客户查询 / 生产规则直改 / 退款冻结执行（`dmz/app.py`）。
- 网关鉴权：服务令牌 + 审计；inner MCP Facade **只为白名单工具提供实现，被禁能力根本不存在**（`inner/app.py`）。
- ⚠️ **差距 G3**：网关未做限流（429）；鉴权为 HMAC 服务令牌，生产须 OAuth/mTLS。

### 9. 审计、密钥与版本体系 — ✅
- 统一审计事件：人员/请求/agent_version/model_supplier/model_version/工具/规则版本/审批轨迹，分_zone 落库可查询。
- 版本：APP_VERSION + schema_version + 规则 version + 端点 version 贯穿。
- ⚠️ 生产化事项（代码已注明）：KMS/HSM 托管密钥、接入银行日志平台/堡垒机。

### 10. 科技人员扩展与发布流程 — ◐
- ✅ 已有：MCP Connector → DMZ 网关（鉴权/审计）→ 内网 Facade 映射白名单 API（非数据库直连）；可读规则目录/合成案例/聚合指标；可提交 Skill/Workflow/规则变更草稿（按 developer 角色鉴权）；沙箱测试工具。
- ⚠️ **差距 G4**：草稿提交后**无审批-发布流水线**（草稿入库后无审批页/版本化发布/回归门槛）。管理员端已有通知/请假审批的交互模式可复用。

## 三、七条验收约束对照

| # | 约束 | 结论 | 证据 |
|---|---|---|---|
| 1 | 数据不出域 | ✅ | 脱敏/映射表/规则库仅内网；DMZ 白名单+DLP+回程校验；外网库无原文无映射 |
| 2 | Agent/模型不做最终裁决 | ✅ | 内网 `rules.evaluate()` 规则裁决 + mandatory_human 强制转人工 + 人工四动作；模型输出仅建议 |

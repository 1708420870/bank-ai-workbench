# 字段级脱敏策略表

> 对应审计编号：**A1 / C3 / X4 补充证据**
> 权威实现：`inner/privacy.py`（识别与令牌化）、`dmz/app.py:_DLP`（形态级二次检查）
> 本表回答一个问题：**到底哪些字段能出域、变成什么样子、什么条件下能还原。**

---

## 1. 字段级策略

| 字段类别 | 识别规则（正则/机制） | 令牌前缀 | 出域形态示例 | 允许出域 | 恢复条件 |
|---|---|---|---|---|---|
| 客户姓名 | 姓名库精确匹配（`PrivacyService._names`，来自 `customers.name`） | `NAME_` | `NAME_001` | **否（原文）** / 是（令牌） | 三元匹配 + 本请求映射存在 |
| 身份证号 | `\b\d{17}[\dXx]\b` | `ID_` | `ID_001` | **否（原文）** / 是（令牌） | 同上 |
| 银行卡号 | `\b\d{16,19}\b`（在证件号之后匹配，避免 18 位被抢） | `CARD_` | `CARD_001` | **否（原文）** / 是（令牌） | 同上 |
| 手机号 | `\b1[3-9]\d{9}\b` | `PHONE_` | `PHONE_001` | **否（原文）** / 是（令牌） | 同上 |
| 金额 | `[¥￥]\s?\d[\d,]*(\.\d{1,2})?` / `\d[\d,]*\s*元` | `AMT_` | `AMT_001` | **否** | 同上 |
| 日期 | `\d{4}-\d{2}-\d{2}`、`\d{1,2}月\d{1,2}日` | `DATE_` | `DATE_001` | **否** | 同上 |
| 商户号 | `\bM-\d{3,5}\b` | `MERCHANT_` | `MERCHANT_001` | **否** | 同上 |
| 意图类别码 | 不脱敏（枚举值） | — | `DISPUTE_PROCESS` | **是** | 无需恢复 |
| 规则摘要 | 不脱敏（人工撰写的对外可公开摘要） | — | "争议受理需 3 项材料" | **是** | 无需恢复 |
| 规则全文 | 不脱敏，但**根本不下发** | — | — | **否（永不）** | — |
| 令牌映射表 | 加密存储（`sealed_value`，密钥 `DATA_KEY`） | — | 不出域 | **否（永不）** | 仅内网 `restore_for_display` 读 |
| 员工工号/角色 | MCP 调用中以 `actor`/`role` 字段出现 | — | `T001` / `developer` | **否**（仅在内网↔DMZ 之间传，不出外网） | — |

## 2. 识别顺序为什么重要（顺序即正确性）

`inner/privacy.py:_ORDER` 固定为：**证件号 → 卡号 → 手机号 → 金额 → 日期 → 商户 → 姓名**。

反例：若卡号（16–19 位）先于证件号（18 位）匹配，则 `110101199001011234` 会被当成卡号令牌化为 `CARD_001`，虽然也脱敏了，但：
- 令牌类型错误 → 恢复时字段语义错位；
- 出域扫描按"卡号残留"规则检查，与真实类型不匹配 → 漏检风险。

所以顺序不是风格问题，是**判定正确性**问题。

## 3. 三道闸门（任一命中即阻断，不"局部剔除后放行"）

| # | 闸门 | 位置 | 失败后果 |
|---|---|---|---|
| 1 | 脱敏自检：脱敏后再扫一遍，残留即抛错 | `privacy.mask()` 末尾 | `ValueError` → 调用方 fail-closed 转人工 |
| 2 | 出域 DLP：形态级扫描（卡号/手机号/证件号/金额） | `dmz/app.py:⑤` | HTTP 451 `CONTENT_INSPECTION_FAILED` + `EGRESS_DENIED` 审计 |
| 3 | 回程敏感内容复检：外网返回同样要扫 | `inner/service.py:_validate_response` 第④项 | 整包作废 → `RESPONSE_REJECTED` → 转人工 |

**为什么不做"剔除后放行"**：局部剔除意味着攻击者只要多塞一个令牌，就能让其余原文随"已过滤"的包一起通过审查——过滤动作本身变成了掩护。所以规则是**整包拒绝**。

---

## 4. 恢复（回填真实值）的三种前置条件

`inner/service.py:restore_for_display(request_id, session_id, emp_id, text)`：

| 条件 | 校验 | 不满足时 |
|---|---|---|
| ① 请求存在 | `db.ticket(request_id)` | 404 |
| ② 会话匹配 | `row["session_id"] == session_id` | **403** + `RESTORE_DENIED(session_mismatch)` 审计（critical） |
| ③ 人员匹配 | `row["emp_id"] == emp_id` | **403** + `RESTORE_DENIED(actor_mismatch)` 审计（critical） |

**恢复后的数据不再外发**：`restore_for_display` 只在响应体内返回给当前员工浏览器，`audit.log("RESTORED")` 只记 `fields`（令牌名列表），**不记真实值**。

## 5. 明文不落盘的位置清单（可审计）

| 位置 | 是否含明文 PII | 复验 |
|---|---|---|
| `inner.db: customers/transactions` | **是**（原始业务库，内网） | 设计如此，需内网权限 |
| `inner.db: token_map.sealed_value` | 加密（AES，密钥 `DATA_KEY`） | `python -c "import sqlite3;print(sqlite3.connect('data/inner.db').execute('select sealed_value from token_map limit 1').fetchone())"` → 密文 |
| `inner.db: events.detail` | **否**（`audit.scrub` 后写入） | 抽查 `evidence/audit/` 导出样本 |
| `dmz.db` | **否**（仅 `events` 表，无客户表） | `sqlite3 data/dmz.db ".tables"` |
| `outer.db: tasks` | **否**（仅脱敏上下文 `sanitized_context`） | `sqlite3 data/outer.db "select sanitized_context from tasks limit 1"` → 令牌形态 |
| 日志文件 | **否**（logger 只记事件名与长度/键名） | `grep -E "\d{16,19}" data/logs/*.log` → 零命中 |

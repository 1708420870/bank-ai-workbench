### Day 1 · 核心链路：脱敏出域 → 外网建议 → 回程校验 → 内网恢复

**纵向切片**：坐席登录 → 打开工单 → 发起 AI 建议 → 看审计。

| 时间 | 内容 | 责任角色 |
|---|---|---|
| 09:00–10:00 | 讲解三区与字段白名单（`docs/13`、`docs/14` §2） | 交付方架构 |
| 10:00–12:00 | 演示：输入含姓名/卡号/手机号的客户描述 → 观察出域报文（DMZ 侧日志）为令牌化形态 | 坐席 + 架构 |
| 13:30–15:30 | 演示：外网返回 → 回程六项校验逐项展示（人为篡改 3 项各触发一次拒绝） | 交付方 |
| 15:30–17:00 | 演示：内网恢复（三元匹配），跨会话恢复被拒 | 安全 |

**放行条件（必须全部满足，逐条打钩）**

- [ ] `data/inner.db` 审计出现 `TOKENIZED` ≥1 条，`detail` 中字段为 `NAME_*`/`CARD_*`/`PHONE_*` 形式
- [ ] `data/dmz.db` 审计出现 `EGRESS_ACCEPTED` ≥1 条，`context_len` > 0 且原文不可见
- [ ] 截取 DMZ 侧收到的报文，`grep` 客户真实姓名/卡号/手机号 **零命中**
- [ ] 篡改签名 → 回程校验失败并转人工（审计 `RESPONSE_REJECTED`）
- [ ] 篡改 `request_id` → 拒绝；篡改 `schema_version` → 拒绝
- [ ] 超长响应（>上限）→ 拒绝（R5 新增用例 `test_r5_overlong_rejected`）
- [ ] 回传含手机号明文 → 拒绝（`test_r5_sensitive_residue_rejected`）
- [ ] `RESTORED` 事件 ≥1 条；跨会话调用 `restore_for_display` 返回 403 且审计 `RESTORE_DENIED`
- [ ] 出域开关为 false 时，任何发起动作被阻断（`test_t07`）

## 第二部分：岗位任务卡

> 每张卡可独立交给对应岗位人员执行，**不看代码、不看设计文档**也能完成。禁止动作明确列出，违反即判不合格。

### 任务卡 1 · 客服坐席（role=`client`）

| 项 | 内容 |
|---|---|
| **任务目标** | 处理 3 条客户反馈，其中至少 1 条需转人工 |
| **输入** | 登录账号（`/login`，坐席页签）；客户反馈列表 |
| **步骤** | ① 登录 → ② 打开「客户反馈 · 工单处理」→ ③ 选一条未处理工单 → ④ 点击生成 AI 建议 → ⑤ 阅读建议与依据 → ⑥ 选择「采纳」或「修改后发送」→ ⑦ 对高风险工单选择「转人工」→ ⑧ 查看结果 |
| **禁止动作** | ① 不得直接向客户发送含卡号/手机号/姓名的原文；② 不得跳过 AI 建议直接改工单状态为已办结（需主管权限）；③ 不得把 AI 建议原文复制到外部聊天工具 |
| **验收点** | ☐ 3 条工单状态正确流转 ☐ 建议区显示"依据摘要"与"待确认事项" ☐ 转人工的工单有明确理由 ☐ 无一条回复含 PII 明文 |
| **异常回退** | 若 AI 建议为空或超时 → 直接转人工，并在工单备注"AI 不可用"，不得自行编造回复 |

### 任务卡 2 · 客服主管（role=`supervisor`）

| 项 | 内容 |
|---|---|
| **任务目标** | 审批 1 张请假 + 审批 1 个科技草稿 + 处理 1 条升级工单 |
| **输入** | 管理员控制台账号 |
| **步骤** | ① 登录（管理控制台页签）→ ② 审批请假 → ③ 进入「变更审批」→ ④ 查看草稿详情与回归门槛结果 → ⑤ 点击「批准」→ ⑥ 点击「发布」→ ⑦ 查看审计 |
| **禁止动作** | ① 不得审批自己提交的草稿（无自审批）；② 不得在回归门槛未通过时强制发布；③ 不得修改草稿内容后直接发布（只能驳回重提） |
| **验收点** | ☐ 请假审批留痕 ☐ 草稿状态 `PENDING_REVIEW→APPROVED→PUBLISHED` ☐ 自审批被拒 ☐ 回归未过时发布按钮不可用或返回 409 |
| **异常回退** | 发布后发现异常 → 执行「回滚」，状态回 `ROLLED_BACK`，通知提交人 |

### 任务卡 3 · 审核员（role=`auditor`）

| 项 | 内容 |
|---|---|
| **任务目标** | 对 1 个 `request_id` 完成全链路审计复核，并抽查 20 条出域记录 |
| **输入** | 审核员账号；一个工单号 |
| **步骤** | ① 登录 → ② 进入审计 → ③ 按 `request_id` 检索 → ④ 核对六要素（人员/请求/规则版本/模型版本/工具调用/人工确认）→ ⑤ 导出 CSV → ⑥ 抽查出域记录中是否含 PII |
| **禁止动作** | ① 不得修改任何工单状态；② 不得导出含客户明文的审计（系统本身不记录原文，若发现即报缺陷）；③ 不得把审计导出上传至外部网盘 |
| **验收点** | ☐ 六要素齐全 ☐ 导出文件可打开且行数>0 ☐ 抽查 20 条零 PII 命中 ☐ 审计中可见 `EGRESS_ACCEPTED`/`MCP_DENIED` 等关键事件 |
| **异常回退** | 发现 PII 残留 → 立即按"重要缺陷"上报，暂停外呼开关 |

### 任务卡 4 · 科技人员（role=`developer`）

| 项 | 内容 |
|---|---|
| **任务目标** | 通过受控 MCP 通道读取规则目录、提交 1 个 Skill 草稿并走完审批发布 |
| **输入** | 科技人员账号；MCP 客户端或管理端"受控工具"入口 |
| **步骤** | ① 登录 → ② 调用 `list_rule_catalog` → ③ 调用 `get_rule_metadata` → ④ 调用 `get_masked_sample_case` 验证样例已脱敏 → ⑤ 调用 `submit_skill_draft` 提交草稿 → ⑥ 用 `get_change_status` 查状态 → ⑦ 等主管审批后确认发布 |
| **禁止动作** | ① 不得尝试任意 SQL（`run_sql`）、原始客户查询（`query_customer`）、生产规则直改（`update_rule_production`）——这些工具**根本未注册**；② 不得在草稿中写入真实客户数据；③ 不得绕过 MCP 网关直连内网 API |
| **验收点** | ☐ 4 个只读工具返回正常 ☐ 禁止工具调用返回 404 且审计 `MCP_DENIED` ☐ 草稿进入 `PENDING_REVIEW` ☐ 草稿未审批前无法发布 ☐ 发布后状态 `PUBLISHED` |
| **异常回退** | 若网关不可达 → 记录错误码，不得改用直连方式；上报网络组 |

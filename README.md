# 银行客服 AI 工作台 · 内外网协同 PoC

> 面向银行客服人员的 AI 辅助工作台。核心命题不是"做一个客服机器人"，而是
> **在不可信的信任边界上安全搬运数据**——客户原始信息留在内网，只有令牌化的
> 抽象意图出域，返回的候选建议由内网规则引擎裁决后才允许复原展示。

架构设计与决策依据见 [`docs/01-系统体系结构草图.html`](docs/01-系统体系结构草图.html)。

## 一、快速开始

### 方式 A：本地三进程（最快，无需 Docker）

```bash
pip install -r requirements.txt
python run_local.py
```

打开 <http://127.0.0.1:8101> 。

三个进程、三个端口、三个独立 SQLite 文件，刻意不合并成一个应用——
如果把三个区跑在一个进程里，"网络隔离"就只是命名，不是边界。

### 方式 B：Docker Compose 三网络（贴合任务书附录 B）

```bash
docker compose up -d --build
docker compose ps
```

`outer` 只接入 `outer_net`，**在拓扑上没有到 `inner_net` 的路由**；
`inner` 只接入 `inner_net + dmz_net`；`dmz` 同时接入两张网，是唯一咽喉点。
隔离靠网络拓扑实现，不靠代码自觉。

### 方式 C：绿色包分发给同事（对方不用装任何东西）

```bash
pip install pyinstaller
python build_desktop.py
```

产物：

- `release/银行客服AI工作台-v<版本>-win64.zip` ← **发给同事的就是这一个**
- `release/银行客服AI工作台-v<版本>-win64/` ← 解压后的形态，可先本地验证

同事侧：解压 → 双击 `启动.bat` → 浏览器自动打开登录页。整包内嵌 Python 运行时
与全部依赖，不需要装 Python、不用连你的电脑；数据落在包内 `data/`，删掉即重置。
另有 `启动-局域网.bat`（`ZONE_HOST=0.0.0.0`，同网段手机可直接访问 8103）。

> 打包形态的选择理由、迁移与备份方式、常见故障处置，见
> [`docs/25-分发与迁移指南.md`](docs/25-分发与迁移指南.md)。

> 三区在线程级隔离只在演示层面成立；给真实客户用之前，仍应以方式 B 的
> 三网络拓扑部署服务端，桌面客户端退化为纯外壳（把窗口指向服务器地址即可）。

## 一·五、登录与账号分发（RBAC）

**系统没有公开注册**。同事的账号只能由管理员在管理端「账号与会话」页发放，
口令私下告知；连续 5 次口令错误锁定 300 秒。

| 账号 | 口令 | 姓名 | 角色 | 入口 |
|---|---|---|---|---|
| a001 | abc123456 | 苏总 | 管理员 | 管理控制台 `/admin` |
| t001 | Tech@2026 | 科技开发 | 开发人员 | 管理控制台 `/admin` |
| b001 | abc122333 | 小梁 | 客服坐席 | 坐席工作台 `/client` |
| b002 | abc122333 | 小杨 | 客服坐席 | 坐席工作台 `/client` |
| b003 | abc122333 | 小刘 | 客服坐席 | 坐席工作台 `/client` |
| b004 | abc122333 | 小黄 | 客服坐席 | 坐席工作台 `/client` |

> 以上为 PoC 演示口令。正式账号由管理员发放，初始口令一律首登强制改密。

访问控制要点（对应验收组 A01–A12）：

- **双入口在登录环节分流**：坐席账号进不了管理端，反之亦然（A02）；
- **坐席只能以本人身份提交工单**，主管可代提交但审计记录双身份（A05/A06）；
- **角色从会话读，不从请求体读**：MCP 调用面板里前端没有机会声明自己是开发者；
- **会话可即时吊销**：停用账号、重置密码、主管手动吊销都会立即踢下线——
  这是刻意不用 JWT 的原因（无状态令牌做不到即时失效）；
- **单会话互踢**（默认开，`SINGLE_SESSION=false` 关闭）：同账号第二次登录
  会吊销第一次的会话，防账号共享（A10）；
- **设备绑定**（`DEVICE_BINDING=true` 开启）：账号绑定设备后，异设备与
  无设备头的浏览器都无法登录（A12）；桌面客户端自动携带设备标识；
- **登录来源限制**：`ALLOWED_LOGIN_NETS="127.0.0.0/8,192.168.0.0/16"` 之类
  的 CIDR 列表可把登录接口限定在公司网段。

分发新账号的流程：管理员登录 `/admin` → 账号与会话 → 填写工号/姓名/账号/
初始口令/角色 → 创建 → 私下把账号口令发给同事。同事首次登录即改走
「重置密码」流程（管理员操作）或直接沿用。

## 二、分区与端口

| 区域 | 端口 | 持有 | 绝不持有 |
|---|---|---|---|
| 内网可信域 `inner` | 8101 | 客户原始数据、令牌映射、权威规则、密钥、审计、裁决权 | —（信任根） |
| 安全交换区 `dmz` | 8102 | 过境中的令牌化载荷（带 TTL） | 客户原始数据、映射表、业务库 |
| 外网 AI 协同域 `outer` | 8103 | 脱敏上下文、任务元数据、办公产物 | 原始身份字段、可复原档案、内网直连路径 |

## 五、故障演练

外网区提供显式故障注入（仅 PoC，不改变数据边界）：

```bash
# 上游超时 → 内网标记 TIMEOUT 并转人工
curl -X POST http://127.0.0.1:8103/outer/api/v1/_fault -H "Content-Type: application/json" -d "{\"mode\":\"timeout\"}"
# 非法结构响应 → Schema 校验失败，响应被丢弃
curl ... -d "{\"mode\":\"bad_json\"}"
# 未知意图码 → 规则引擎拒绝自动处理
curl ... -d "{\"mode\":\"unknown_intent\"}"
# 恢复
curl ... -d "{\"mode\":\"ok\"}"
```

## 六、PoC 边界（必须知道的事）

以下不是"待优化项"，而是**有意为之的降级**，上生产前必须替换：

1. **加密**：`common/crypto.py` 用 HMAC 密钥流做确定性加密，便于令牌查重。
   生产必须换成 KMS/HSM 托管的 AEAD（AES-GCM）。
2. **密钥管理**：共享密钥走环境变量。生产走证书体系与密钥轮换。
3. **重放检测**：进程内字典。生产落带 TTL 的分布式存储。
4. **身份认证**：已完成本地口令体系（PBKDF2-200k、失败锁定、设备绑定、
   单会话互踢）。生产再接银行 SSO/MFA 即可，RBAC 骨架不变。
5. **牛马仕（Bull Hermes）/ WorkBuddy**：牛马仕内网算力已接真实端点
   （`MODEL_IMPL=real`，默认 `HERMES_BASE_URL=http://106.55.2.189:8000/v1`
   的 Qwen3.5-9B-AWQ，vLLM OpenAI 兼容协议；算力不可达时自动降级确定性
   Mock 并打 `degraded` 标记，绝不 fail-open）。测试固定走 Mock 保证可离线
   复现。外网 WorkBuddy 适配器仍为 Mock，真实接入只替换 `outer._run_agent()`。
6. **DMZ 的检测能力有上限**：DMZ 不持有客户名单，只能查"形态"
   （卡号/手机号/证件号的字符模式），查不出"这个中文名是不是客户"。
   姓名级检测只能在内网完成——两道闸失效模式不同，不是简单重复。
7. **单机模式下"网络隔离"由代码护栏近似**：`common/egress.py` 在每个区
   发起调用前校验目标端口白名单。真正的强制在 Docker/银行网络层。

## 七、换人接手要点

- 先读 `docs/01-系统体系结构草图.html` 的第 11 节（10 条 ADR），
  那里记录了**被否决的选项**，比结论更能防止返工。
- 改动顺序：契约（`common/schema.py`）→ 隐私（`inner/privacy.py`）→ 编排
  （`inner/service.py`）→ 前端。**隐私服务是唯一不能返工的部分**，
  它必须在 UI 定稿之前稳定。
- 新增出域字段 = 改契约 + 改扫描 + 补测试，三步缺一不可。
- 任何"为了让演示更顺畅"而绕过网关的改动，都会让 T20 失败。
